# 情シスの一年 v0.7 — 出来事と日常業務

2026-09-28。対象はCompanyYear。SampleSceneの内容は変更していない。

## 変更前と変更後

以前は7分類・12か月分の固定の出来事だった。数値と正常／異常の判定は種で変わるが、毎年の出来事の種類は同じだった。
今回、攻撃・不正利用の題材29件と運用トラブル11件、合計40件をカタログ化した。相談・ニュース・社員の報告・兆候・調査結果・備え・知識を一つの出来事に結び付ける。
別に任意の日常チケット18件を追加。背景だけの文章ではなく、工数・社員の成長・報酬・委任・月報へつながる。

### 年間の組み立て

- 4月は、バックアップと復元確認を題材にした導入イベントで固定。
- 他の11か月は抽選。7・8・11・1月の4か月は運用トラブル、それ以外は攻撃・不正利用の題材から選ぶ。年度内では同じ出来事を繰り返さない。
- 6・9・12月と3月の負荷、四半期報酬はv0.6の仕組みを維持。今月の相談から備えの方向は分かるが、正常か異常か・被害の規模は未確定。
- 日常チケットは月1件、18件から重複なしで抽選。共同対応は1工数・担当者経験+1・社員経験+1。担当社員Lv.2と引継ぎ手順があれば0工数で任せられ、社員経験+1。
- チケットの報酬は予算+3万円、相談文化+3、経営の信頼+3、疲労-6のいずれか。改善投資を優先して後回しにもできる。未対応への罰則はない。
- 各出来事の社内依頼は、設備の整備と現場の行動の二つの達成方法を持つ。相談から何を調べるか・何を導入するかがつながる。

## 題材の範囲

IPAの順位を発生確率やゲーム内の強さに換算していない。複数の区分に関係する題材もある。

| IPA 2026の組織向け区分 | 収録した題材の例 |
|---|---|
| 1 ランサム攻撃 | 暗号化、復元元の保護、情報の持ち出し、部門間の横展開、侵害を名乗る投稿の真偽確認 |
| 2 サプライチェーン・委託先 | 保守ID、配布元の侵害、委託SaaSからの波及 |
| 3 AI利用のリスク | 顧客情報の入力、外部文書からの指示、生成した規程・案内の誤り |
| 4 脆弱性悪用 | 公開機器、Webライブラリ、更新できない旧端末 |
| 5 標的型攻撃 | 業務に似せた添付、連携アプリへの同意、認証済みセッションの悪用 |
| 6 地政学的リスク | 外部情勢を背景とする妨害と事業継続。動機不明の侵害投稿をこの区分へ断定していない |
| 7 内部不正 | 大量取得、特権IDの共用、契約終了後の権限 |
| 8 リモートワーク環境 | VPN認証情報、社外端末紛失、遠隔支援を装う接触 |
| 9 DDoS | Web受付の負荷、通信回線の負荷、外部情勢に伴う妨害 |
| 10 ビジネスメール詐欺 | 振込先変更、声を使った承認要求、メールスレッドへの割込み |

運用トラブル11件は、証明書、SSO変更、端末更新、容量不足、バッチ、保存機器、誤削除、SaaS障害、社内ネットワーク、共有設定、自動転送。攻撃と通常の変更・誤操作を同一視しない。
日常チケット18件は、入社、退職、異動、外注ID、SaaS棚卸し、問い合わせ受付、FAQ、当番引継ぎ、証明書点検、バックアップ点検、監視通知整理、更新予定、不審メール相談、支払確認、業務AI相談、自動回答の引継ぎ、端末返却、代替業務点検。

## 調査資料とゲームへの取り込み

公表された論点を架空の社員45人の会社に組み直した。実企業の被害・機器構成・実名・費用を再現するものではない。実際の対処は製品・契約・被害の状況で異なり、このゲームの数値を実務へ転用しない。

## ルール上の違い

16種類の効果プロファイルを使い、同じ対策の効き方を出来事ごとに変える。文章だけ40件に増やしたものではない。

- 保存データの破損・暗号化・削除には復元の備えが効く。DDoSや流出をバックアップで取り消す効果はない。持ち出しを伴うランサムの損失は簡略化された合算で、復元しても流出が消えるわけではないと説明する。
- MFAは認証入口と盗まれた認証済みセッションで効き方が違う。社外端末の紛失で保存データを守る加算はしない。端末管理の細かな暗号化・消去操作自体は未実装。
- 更新・SSO変更・SaaS停止では、切戻しと代替業務へ重点配分する方式が強くなり得る。広く止める方式は、攻撃の拡大を抑える利点と正常業務を止める不利益を持つ。
- 全方式で基本の封じ込め・証拠確認・安全確認を行う前提。重大な攻撃を放置して復元だけ行う選択ではない。
- 数値は学習した手順の完全な実行を表すものではない。SC範囲の網羅・資格取得の保証はしない。

## 保存と互換性

新規年度だけ`eventRules=1`で抽選し、12件のイベントIDとチケットIDを保存する。行動・プレビュー・保存読込で再抽選しない。月報には出来事のID・当時のタイトル・知識ID・日常業務の対応方式を残す。
旧セーブは従来の月固定方式を維持し、日常チケットや過去の記録を後付けしない。v0.7を試すときはニューゲームを選ぶ。
純粋ルールの従来テストは旧コンストラクター`OpsState(seed)`、新方式は`OpsState(seed,true)`で別に確認する。本番のニューゲームは新方式。
