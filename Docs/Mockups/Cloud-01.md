# クラウドの作業 01 — 対戦のミニゲームのHTML手本（Claude、2026-10-03）

**この作業は、旧アカウントのクラウドセッション（スマホのClaudeアプリ「Code」）で行う。** 新アカウントのClaude（PC）とCodexが同じリポジトリで並行して作業しているので、次の決まりを守る。

## 0. 最初に必ず

1. `CLAUDE.md`（自動で読まれる）と`Docs/引き継ぎ_旧アカウント_20261003.md`を読む。返答はすべて日本語。
2. **作業の元のブランチは`feature/title-quiz-ending-flow`**（`main`は初期状態のままなので使わない）。自分の作業用のブランチを作り、そこにコミットする。最後にPR（`feature/title-quiz-ending-flow`へ）を作る。
3. **新しいファイルだけを作る。** `CLAUDE.md`・`AGENTS.md`・`Docs/Dev-Status.md`・`Assets/`の下・既存の手本は書き換えない（Codexと新アカウントのClaudeが触るため）。例外：`Docs/引き継ぎ_旧アカウント_20261003.md`の8章の最後に、やったことを日付つきで1〜3行追記する。
4. このクラウドではUnity・GPU・`Artifacts/`・内蔵ブラウザは使えない。HTMLと文書だけで完結させる。

## 1. 作るもの

`Docs/Mockups/proto-h-duel.html`：10大脅威の子と1対1で戦う、ブラウザで遊べる手本。加藤さんの承認を得るためのもの（ゲームにはまだ入れない）。

### 材料（すべてリポジトリにある）
- 10人の設定・名前（すべて仮）・色・題材・台詞：`Docs/Rivals-Characters-2026-10-03.md`
- 共通の印・決まり・対戦の案：`Docs/Rivals-Persona-Design-2026-10-03.md`（「対戦のミニゲームの案」の章）
- 技（攻撃手法）と攻撃の糸口6つ・効く設備：`Assets/Scripts/CompanyOps/OpsThreatCatalog.cs`（Next-20で入ったデータ。読むだけ）と`Docs/Rivals-Threat-Research-2026-10-03.md`の00章（IPAの解説書で確かめた用語）
- 画面の作り・文字・色の決まり：既存の手本（`Docs/Mockups/proto-f2-blocks.html`・`proto-g-restore.html`・`proto-e-logs.html`）と同じ作り方（1ファイル、`#shot=`で場面を出せる、日付を種にした「今日の一問」）にそろえる。書体は本文Zen Kaku Gothic New、見出し・数字M PLUS Rounded 1c。**絵文字は使わない**（ゲームのフォントに無い）。

### 遊び方（案。手本の中で遊んで確かめられるように）
- 相手（例：クリプタ）は毎ターン、次に使う**技を予告**する（技の名前・攻撃の糸口・ひとことの台詞）。
- プレイヤーの手札は**備え**のカード（今の設備：`patch`・`edr`・`mfa`・`inventory`・`backup`・`education`など。`OpsThreatCatalog`の`weaknesses`と糸口の対応を使う）。
- 予告された技の**糸口に効く備え**で受けると「防いだ」（旧版のパリィの考え方）。効かない備えだと、被害か停止のゲージが増える。
- 何ターンか耐えるか、相手の技をすべて受け切ると勝ち。負けても「どの備えなら防げたか」を必ず見せる（性弱説：責めない、学びにする）。
- 勝ったとき・負けたときに、相手の負け台詞・勝ち台詞（設定書のもの）と、効いた備えの名前を出す。
- 10人から相手を選べる画面と、1人ずつの対戦画面。相手の色・瞳の形・頬の紋は、絵の代わりに図形で表す（絵はまだ確定していない）。

### 正しさの決まり
- 技の名前と説明は、`OpsThreatCatalog`と調べの00章の用語・意味のまま使う。新しい技を足すなら、IPAの解説書など一次資料で確かめ、確かめられないものは足さない。
- 「この備えで必ず防げる」とは書かない（「被害を抑えられる」「入口をふさぐ」など、言い過ぎない表現）。点検の決まりは`Docs/Fact-Check-2026-10-02.md`の1章。
- 実在の会社・製品・国・IPアドレス・ドメインを出さない。
