# 次の実装 19 — テストの回数と組み分けを最適にする（Claude、2026-10-03）

**Next-18の完了報告が終わってから始める。** 加藤さんの判断（10/3）：「テストは大事。でも最適な回数で進め、時間と使用量を節約したい」。数値・ルール・見た目は変えない。テストの中身（確かめていること）も減らさない。**変えるのは、いつ・どの組を・何回流すか。**

## 今の様子（Next-18の全件1回目の記録から）

- 全件294件で約38分。決まりで2回流すので約76分。途中で失敗すると直して流し直すため、Next-17では全件を5回以上流した。
- 長いもの：「3つの役で5年度を画面のボタンから通す」3件で約12分（全体の3分の1）。ゲームパッドで6本（約2分）、画面の撮影のテスト（各20〜45秒）が続く。

## ① テストに組の印を付ける

- `[Category("Long")]`：3つの役で5年度を通す3件、ゲームパッドで6本を最高ランクまで遊ぶ、1年分をゲームパッドで通す。
- `[Category("Capture")]`：画面を撮影して保存するテスト（`Next*UI_*`の撮影、ストア・宣伝用の撮影はすでにExplicit）。
- 印の無いものが「普段の組」。組の分け方で件数が増減しないこと（全部の合計が今の294件と同じ）。

## ② 流し方の決まり（CLAUDE.md・AGENTS.mdの4章・5章に書く。両方を同じ内容に）

| 場面 | 流すもの |
|---|---|
| 各項目のコミット前 | 関係するテスト＋コンパイル確認（今と同じ） |
| 指示のまとまりの最後 | **普段の組＋Captureを1回**。失敗したら直して、**失敗したテストと関係するテストだけ**を流し直す（全件を最初からやり直さない） |
| Windows版を作り直すとき | **Longを含む全件を1回**。そのうえで、普段の組をもう1回（連続で通ることの確認）。Longは1回でよい |
| 公開用（Steamなど）の版 | Longを含む全件を2回連続（今の決まりと同じ） |
| 数値を変えたとき | 今と同じく、Verify系と1年だけの遊びのCSVのSHA256 |

- 途中で中断した実行は数えない（今と同じ）。テスト後にフォントの作業用データとPlayerPrefsが戻ることの確認も今と同じ。
- GPUの取り合い：Claudeの短い声の生成は待たずに流れることがある（`Docs/Voice/Irodori-Direction-Rules.md`の2e）。撮影のテストが時間切れになったときは、まず取り合いを疑い、同じテストだけを流し直す。
