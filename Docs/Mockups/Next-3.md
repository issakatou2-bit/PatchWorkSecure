## ② 判断の深さ（推奨案A〜E）

`Docs/Decision-Depth-Design-2026-09-29.md`の2章と4章。要点：
- A 状況の把握（0〜4）：未調査+2、監視なし+1、台帳なし+1、困りごとの泡の手がかり−1（③）。事件画面にゲージで出す。
- B 限定の見落とし：限定の被害に「把握不足×広がりやすさ×3万円」を足す（分離の効果`containment/3`で軽減）。広がりやすさは`OpsEventProfile`に項目を足す（ランサム・委託先・脆弱性・標的型・在宅接続=2、変更・保存・サービス・DDoS=0、他=1）。
- C 限定の調査費：対応費に「把握不足×2万円」。
- D 発生の時間帯：約1/3が夜間・休日。そのとき「広く止める」の停止9h→2h。分離Lvごとに通常時も−2h（下限3h）。年度の抽選と同じ種で決め、保存する（旧セーブは「業務時間」）。事件画面に札（「金曜の夜」「連休中」など）。
- E 復旧の対応費：4万円→2万円。
- 数値は`OpsCatalog`の定数に置く。`Estimate`（公開の見積もり）にも同じ計算を通し、**未確認の真相（benign・Severity）をゲージや見積もりに漏らさない。**
- 検証：`./Tools/Verify-CompanyOps-Depths.ps1`で、限定40〜55%、迷える選択肢（非優越候補）平均1.9以上、各方針の完走率が現状から±5ポイント以内。比較用の写し：`py -3 Tools/Sim-DecisionDepth.py <作業フォルダ> "3 2 0 0 0 1 2 2 2"`（本体を変えた後は、この写しと同じ結果になるはず）。

## ③ 困りごとの泡

モック：`Docs/Mockups/planning-bubbles.html`（押すと弾ける・音・報酬の数字・手がかりのカード。`#demo`で自動再生）。案の背景：`Docs/Ideas-Office-Bubbles.md`。

| 項目 | 仕様 |
|---|---|
| 出る数 | 月4個。計画画面の開始時に、部屋の上へ0.6秒ずつ時間差で浮かぶ。年度の種で決める |
| 種類 | 通常（青）：紙づまり（執務室）、PCが重い（執務室）、パスワード（執務室）、来客Wi-Fi（受付）、プロジェクタ（会議室）、宅配の端末（倉庫）から3個 |
| 相談の泡（ピンク） | 月に1個、50%で出る（出ない月は通常を1個足す）。弾くと、その月の出来事の社員の声（`OpsEvent.staff`＝もともと公開の情報）を「今月の手がかり」のカードで見せ、規則Aの把握不足を−1（月1回まで） |
| レア（金） | 各泡が3%で金色になる。中身は見た目と反応だけ：社員のお礼カード（短文）、ひなたの特別な掛け声（`extra_*`）。数値の得はつけない |
| 通常の報酬 | 信頼+1／相談文化+1／疲労−1のどれか（泡ごとに固定） |
| 工数・罰則 | 工数は使わない。計画の確定で残りは消える。罰則なし |
| 演出 | 出現は拡大して弾む、ゆっくり漂う。押すと縮んでから弾ける、しずく8粒、報酬の数字が上へ。連続で弾くとSEの音程が3個目から上がる。レアは金の縁・回る点線・しずく14粒・3音 |
| 表示 | マップ左上に「困りごと n / 4」。ひなたの立ち絵・吹き出し・行動ボタンと重ならない位置に置く |
| 保存 | 弾いた泡・手がかりの有無を保存（`OpsSaveStore`）。旧セーブは泡なし |

- 自動方針（`Tools/CompanyOpsDepthChecks.cs`など）：深度1以上の方針は相談の泡を必ず弾く、深度0は半分の月だけ弾く。②の検証はこの条件で流す。
- 泡はタッチ・マウスとも1回で弾ける大きさ（直径70px以上）にする。
