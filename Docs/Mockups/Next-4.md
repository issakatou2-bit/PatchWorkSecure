# 次の実装 4 — 山場の目標（レース）と年間ランク5段（Claude、2026-09-29、加藤さん承認済み）

前提：`Docs/Mockups/Next-3.md`（特に②判断の深さ）が終わっていること。設計と数字の根拠は`Docs/Peak-Goals-Design-2026-09-29.md`。

## ① ルール（`OpsCatalog`の定数と`OpsState`）

| 山場 | 目標 |
|---|---|
| 6月 | 被害8万円以下・停止8h以下 |
| 9月 | 被害5万円以下・停止6h以下 |
| 12月 | 被害3万円以下・停止4h以下 |
| 3月（決算） | 被害6万円以下・停止7h以下 |

- 山場の月の`Resolve`で判定する。達成：信頼+6、予算+8万円、年間+60点、勲章「山場の盾」。未達：信頼−4のみ（予算は減らさない）。
- 結果を`OpsOutcome`と保存に残す。旧セーブは目標なし（従来どおり）。
- `AnnualScore`に山場の加点を足し、`Rank`を5段にする：SS 1950以上、S 1750以上、A 1450以上、B 1100以上、C それ未満。
- 数値はすべて定数にする（試遊の後で詰める）。

## ② 画面

- 計画画面：「一年の歩み」の山マークを押すと、その山場の目標と、今の備えでの**見込み**を出す。見込みは公開の見積もり（`Estimate`）から計算し、予測の見た目にする（確定・真相を使わない）。
- 計画画面・月報：「次のランクまであと○点」（小さな帯）。
- 事件画面：山場の月は上部に目標の帯（「9月の山場　目標 被害5万円以下・停止6h以下」）。各対応の見積もりが目標に届くかを、色で示す（予測の見た目）。
- 結果：達成は、発動カットインと同じ格の演出と勲章の付与。未達は、月報で「何があれば届いたか」を1つ（`potentialInvestmentEffects`の先頭）。
- 年間評価：5段のランク文字（SSは金、Sは虹色の縁など、上ほど豪華に）。獲得した勲章を並べる。
