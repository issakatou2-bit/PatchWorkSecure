# Next-17 ゲームパッド操作

## ① 通常画面

- Input System の `Gamepad` を使い、南ボタン＝決定、東＝戻る、Start＝設定、十字キー/左スティック＝近い選択肢へ移動。Xbox/PS/Steam Deckで同じ配置。実機確認は未実施。
- 既存の `OpsButtonFeedback` / `OpsCardLift` / `OpsPlanningHover` の選択表示を再利用。新しい絵・UI部品を追加しない。設定のスライダーは左右で5%ずつ変更、一覧は選択先までスクロール。
- 開いている窓だけを選択対象にし、月報は次の月、計画は調べるを初期選択。ガイド中は案内先と説明を飛ばす操作を選べる。
- 日記帳の既読ページはLB/RBで前後へ。通常の月報からの日記では未読の未来ページに進まない。
- 既定UIアクションを実行時コピーし、ゲームパッドの決定/移動が二重に入らないようにする。元のアセット・シーン・マウス操作は変更せず、破棄時に元へ戻す。既定の全デバイスSubmitをキーボードEnterに限定。
- 関係分：Next17Menus 1/1、既存Next15Displayの設定保存 1/1。両解像度の撮影と既存画面/モックとの比較を `Artifacts/Next17/` に保存。`title-hover.png` は初期撮影時のファイル名で、マウス位置のヒット検査後の画面（ホバー入力そのものではない）。ホバーと選択の共通表現は既存コンポーネントの実装を維持。

## ② ミニゲーム

- B端末/部屋/道具、C問題なし/報告/リンク確認、D拒否/許可、Eログの行、G仕組みのノードは既存ボタンを十字キー/左スティックで選びAで操作。
- F2は「作業をAで選択→マスを選択→Aで置く」。Xで回転、Bで作業へ戻る。置いた作業を選び直して持ち上げられる。既存のクリック配置と同じ判定を呼ぶため、ドラッグカーソルの速さや新しい自動配置を難しさに加えない。マウスのドラッグ/R/ホイールは残す。
- 操作は開始説明に文字だけで追記。Cリンクの選択では、既存のマウスホバーと同じ行き先を表示する。開幕の設定中は開幕を止めて操作できるが、ミニゲームの制限時間は止めない。
- `InputTestFixture` の仮想ゲームパッドで、タイトル→12か月→年間評価、六本のSランク、回転/置き直し、LB/RBの既読ページ送り、初回ガイド、マウス/キーボードへの持ち替えを確認。関係5/5、3アセンブリ成功。Windows実機パッドの試遊は未実施。
- 通しテストの種はTestModeだけで14に固定して再現。通常起動の種/抽選は変えない。自動プレイヤーは検証用に解答データを参照するため、人間の難易度/学習効果を測ったものではない。
- 採点試遊中の重い撮影が短い回答時間を消費したため、採点試遊と写真用テストを分離。写真用だけ一時的にホストを止め、1280×800/1920×1080で同じ選択を撮影。ゲームの時計/採点コードは変更しない。
- 比較：通常画面は今回の変更前撮影。六本は承認モックと前版Next-15の既存部品撮影も併記。前版とは問題/時間/設備が異なるので、数値の一致を視覚比較の判定に使わない。S判定は別の操作テストで確認。
- OpsCatalog、OpsState、各ミニゲームの採点/制限時間コードに変更なし。50点も従来結果のまま。
- 共通の選択枠は警告枠とグラデーションの後に生成する描画順へ。感染の警告が選択枠を上書きせず、枠の青も背景の色で暗くならない。既存の同じ枠をホバー/選択で共有。最終関係5/5、既存F2の配置/回転/ドラッグ/自動化/結果/50点回帰1/1、3アセンブリ成功。
- 関係分の検証で増えたHeadingDynamicの作業字形は、開始時のUnity保存パッケージから復帰。設定15キーの存在/型/値、フォント8個のSHA256一致、一時シーン0を確認（`preservation-before-full.json`）。作業前からの未コミットフォント/設定はそのまま保つ。
- 設定の音量スライダーは、既存のつまみのOutlineを共通の青い選択色へ切り替え、選択を離れる/マウスへ持ち替えると元の輪郭色へ戻す。追加部品なし。画面切替で破棄された選択対象をUnityのnull判定で扱う。両解像度を再撮影し、`settings-slider-before-after.png`で輪郭色の差を確認。関連5件のうち4件が成功後、仮想キーボードの接続を1フレーム待つよう修正して持ち替え1/1も成功、3アセンブリ成功。

## 最終確認

- Verifyは今回の最終版で1回実行。Core / CompanyOps / Personas / ThreeYears / EndlessYearsは成功。Depthsは従来と同じ最適化完走率58%→85%（+27pt）で未達。±5ptの基準は緩めず、成功扱いにしない。
- 1年だけの900年度・10,779月はNext-8変更前とSHA256一致。年度 `44EE642013CE5D216A40C75AFA8F8D718EB650E9EFF98087861613D7CCB7FA58`、月 `830D58BB7C57A016EB67DCCA407B68B5A0E9465CE4776211C90DF86CEFDF2C63`。
- 3年本編2,160挑戦は初回225/540（41.67%）・4回目まで365/540（67.59%）で不変。終わりなき年度900挑戦の `runs.csv` / `summary.csv` もNext-12の確定版とSHA256一致。考える6方針の中央6.50〜7.75年・最長8.33年・SS60/600は不変。
- 最後の選択枠の描画順修正後の写真から、変更前/承認モックとの比較を作り直した。選択枠と感染警告枠が独立して見えること、文字や既存配置を選択枠が覆わないことを確認。F2のマス数やCの問題数など、種/設備による差は変更前写真と一致させたものではない。
- 初回の全件実行でNext13Speedの「開始説明は2行」という旧期待値が失敗したため、その実行は中断した。従来の短縮した遊び方2行を全文一致で維持し、追加指定のパッド操作1行も別に全文一致で検査するよう更新。関係3/3、3アセンブリ成功。演出速度/制限時間/ルールは変更しない。
- 続く実行も、撮影で見つけたスライダーの選択の分かりづらさを修正するため中断。中断時はテスト全体の最後の復帰処理が走らなかったため、開始時の記録から15設定を存在/型/値ごと復帰した。中断分は全件成功に数えない。
- 全件内では、前の画面の実デバイスを参照するUIアクションのキャッシュがInputTestFixtureの別入力システムへ持ち込まれ、Next17以降にIndexOutOfRangeExceptionが連鎖したため中断した。テスト用の切替前後で既存UIを無効化/破棄し、関連するInputActionMapの実行状態をDisposeしてから入力システムを切り替える。ゲーム本体の挙動・入力定義アセットは変更しない。実入力の画面から仮想入力への移行を含む関連5/5、同じPlayMode内の実入力→仮想入力→実入力の往復1/1、3アセンブリ（追加警告なし）を確認。
- 修正後の全PlayMode2回は未完了。設定/フォントの最終復帰とWindows私的試遊版の更新は、この全件確認後に行う。
