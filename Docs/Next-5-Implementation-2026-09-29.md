## 承認された結果の補正

元の仕様文の厳密な見積もり内への切り詰めと50点完全互換は、現行の結果が見積もり外になる場合に両立しない。加藤さんの追加指示を正とする。

- **50点：現行の結果そのまま。切り詰めない。**
- 50点以外：現行の結果に `f = 1 - 0.4 × (score - 50) / 50` を掛け、整数化。その後、被害・停止ごとに `[min(現行結果, 公開見積もり下限), max(現行結果, 公開見積もり上限)]` に収める。
- 元から見積もり外の結果を、点数によってさらに外側へ広げない。見積もりの表示は「目安の幅で確率ではない」のまま。未確認の真相を見積もりへ入れない。
- 実は正常な事件では感染を一切発生させず、怪しい「？」だけを出す。正常端末を止めるほど減点。真相・感染した総数は結果画面で初めて出す。本編の感染数は**見えている感染**だけ。
- 採点は `100 - 止めきれない感染×12 - 感染した総数×3 - 正常なのに止めた端末×4`。0〜100へ収める。元の HTML の旧採点式ではなく、Next-5 の採点式を使う。

数値は `OpsCatalog`、ロジックは `OpsMinigame` / `OpsContainmentMinigame` / `OpsState`、画面と演出は `OpsGame.Minigames` / `OpsGame.Containment` / `OpsMinigameVisual` に分離した。
