# 緊張と目標 — 山場の目標（レース）と年間ランクの段階（Claude、2026-09-29、案）

根拠：判断の深さの推奨案（`Docs/Decision-Depth-Design-2026-09-29.md`）を入れた状態の自動プレイ900年度（`Tools/Sim-DecisionDepth.py … "3 2 0 0 0 1 2 2 2"`の`years.csv`・`turns.csv`）。人間の試遊ではない。

## 1. 今の問題（数字）

- **年間ランクがすぐ頭打ちになる**：A（1350点以上）に、慣れた方針の99〜100%が届く。上を狙う理由がない。全体の点数は10%点1106、中央1645、90%点1881。
- **後半ほど楽になる**：無事（被害0・停止2h以下）の月の割合は、5月4%→8月68%→1月91%。設備がたまるほど楽になり、年の後半に山がない。ウマ娘ならレースは後半ほど厳しくなる。
- **山場（6・9・12・3月）に目標がない**：負荷が上がるだけで、勝ち負けの手応えがない。

## 2. 案：山場を「レース」にする

ウマ娘の育成で、目標レースへ向けて鍛える流れと同じ形にする。

| 山場 | 目標（被害・停止） | 達成率の見込み（気軽な方針／考える方針） |
|---|---|---|
| 6月 | 8万円以下・8h以下 | 41%／64% |
| 9月 | 5万円以下・6h以下 | 45%／70% |
| 12月 | 3万円以下・4h以下 | 46%／73% |
| 3月（決算） | 6万円以下・7h以下 | 29%／56%（最後の山として一番厳しい） |

- 目標は年度の始めから見せる（ウマ娘の目標レース一覧に当たる）。計画画面の「一年の歩み」の山マークを押すと、目標と、今の備えでの**見込み**（公開の見積もりから計算した予測。確定ではない見た目で）を出す。
- **達成**：信頼+6、予算+8万円、年間+60点、「山場の盾」の勲章（年間評価に並ぶ）。発動カットインと同じ格の演出、ひなたの専用の声。
- **未達**：信頼−4だけ。予算は減らさない（性弱説。致命傷にしない）。月報で「何があれば届いたか」を1つ示す（既存の`potentialInvestmentEffects`）。
- 人間は目標に向けて備えるので、上の達成率より上がるはず。上がりすぎたら目標を締める（数字は`OpsCatalog`の定数）。

## 3. 案：年間ランクを5段に

| ランク | 点数（案） | 見込み |
|---|---|---|
| SS | 1950以上 | 最適化・深掘りの上位 |
| S | 1750以上 | 考える方針の多く |
| A | 1450以上 | 気軽な方針の多く |
| B | 1100以上 | 初学の多く |
| C | 1100未満 | |

- 山場の達成で点数が増えるので、しきい値は実装後の検証で詰める。目安は、SSが全体の約1割、Sが3割、Aが3割。
- 計画画面と月報に「次のランクまであと○点」を出す（上を狙う理由になる）。
- 年間評価の演出は、ランクが上がるほど豪華にする（SSは専用の一枚絵、キャラの主役絵の出番）。

## 4. 後回しにするもの（次の段階）

- 難易度の段階（やさしい／ふつう／むずかしい）：目標としきい値を変えるだけで作れる。上の案が固まってから。
- 兆候の連鎖：放置した相談・兆候が翌月の事件を重くする。泡の手がかりと組み合わせる。
- 3年のキャンペーン：年ごとに山場の目標と新しい仕組みを足す。

## 5. Codexへの実装指示（Next-3の完了後。判断の深さの規則が前提）

1. `OpsCatalog`に山場の目標（月・被害・停止）と報酬・罰の定数、ランクのしきい値を置く。
2. `OpsState`：山場の月の`Resolve`で達成を判定し、報酬・罰を反映。結果を`OpsOutcome`と保存に残す（旧セーブは目標なし）。`AnnualScore`に山場の加点、`Rank`を5段に。
3. 計画画面：一年の歩みの山マークに目標と見込み（公開の見積もりのみ）。「次のランクまであと○点」。
4. 事件画面：山場の月は、目標の帯を上部に出す（「9月の山場 目標 被害5万円以下・停止6h以下」）。見積もりが目標に届くかを色で（予測の見た目）。
5. 結果：達成なら発動カットインと同じ格の演出と勲章、未達なら月報で「何があれば届いたか」。
6. 検証：`Verify-CompanyOps-Depths.ps1`に山場の達成率（方針別）とランクの分布を出す。目安は上の表の±10ポイント、SS約1割。完走率は判断の深さの実装後と比べて±5ポイント以内。

## 6. 実装後の結果と、試遊後の調整案（Claude、2026-09-29）

GPTの実装（`Docs/Next-4-Implementation-2026-09-29.md`）で、山場の達成率は全8比較が目安±10ポイント以内。外れたのは2点。加藤さんは「指定数値のまま試遊」を選択したので、**試遊の後に**判断する。

1. **SSが多すぎる**（28.8%、目安約10%）。900年度の得点の分位（10/30/50/70/90% = 1151/1563/1793/1933/2135）から、目安の分布（SS 1割・S 3割・A 3割・B 2割・C 1割）にするしきい値は **SS 2135／S 1880／A 1563／B 1151**（今は1950/1750/1450/1100）。
2. **最適化方針の完走率が58%→85%**（+27ポイント）。山場の予算報酬+8万円が、予算を使い切る方針を助けている。緊張を残すなら、予算報酬を+4万円に下げるか、信頼の報酬だけにする案。どちらも`Verify-CompanyOps-Depths.ps1`で比べてから決める。
