# v0.5 試遊・仮想評価と改善記録

対象：Unity版「情シスの一年」。実施日：2026-09-26。

## 検証の位置付け

人間の専門家・初見プレイヤーを集めたユーザーテストではない。
ゲーム設計とセキュリティ教育の2役を別々のAI評価エージェントへ依頼し、主担当が再現・採否を判断した。
初心者・効率重視・育成好きは「仮定した判断規則」であり、感想を創作して満足度を付けていない。
自動操作によるUnity画面の試遊、純粋C#による再現可能なシミュレーション、一次資料の調査を組み合わせた。

## 発見した問題と今回の変更

| 観点 | 検証で分かったこと | 変更 |
|---|---|---|
| 選択の意味 | 5方針×500年の変更前検証で、予測を比較する規則は復旧方針を一度も選ばなかった | 復元連携・処理再開連携を、対象の事件と重点配分に結び付けた |
| 育成の見通し | 成長目標は読むだけ。購入比較も限定対応に固定されていた | 成長目標から部品となる整備へ移動。購入前に3方針の予測を切替 |
| 結果の納得 | 全設備なしとの総差だけで、何が役立ったかを判断しづらい | 月報に設備別の比較と、予防・影響限定・復旧の内訳を追加 |
| 経営の抜け道 | 追加予算を受け取り、未達でも資金を保持できた | 新しく受けた追加予算は、整備の約束未達なら全額返却。申請画面にも明記 |
| 社内事情 | 休暇の応援調整は疲労8を防ぐだけで、通常の休息−18に劣る場合が多い | 休暇月の調整と休息を同じ効果に統合。1工数で休息＋追加疲労防止、二重使用不可 |
| 成長の返答 | 相談文化100でも「怒られそうで聞けない」という社員の固定台詞 | 教育導入＋文化65で経理の森さんの6月・12月の相談を分岐 |
| 誤学習 | バックアップが混雑にも、復元訓練が送金詐欺の停止にも効いていた | データ復元対象を4月・1月・3月に限定。性能・処理の再開は別の連携に分離 |

### 連携の内容

- 復元：バックアップ＋復元訓練。データ復元が必要な月に「復旧を優先」。連携Lvごとに復旧対応力+6、さらにデータ被害−3万円・停止−3h。連携Lvは2設備の低い方。
- 再開：自動化＋引継ぎ手順。7月・8月に「復旧を優先」。連携Lvごとに対応力+5・停止−3h。混雑時の処置は不要な定期処理の延期と受注処理への配分として説明する。
- 金銭被害・停止は0未満にならない。正常な活動では連携成功と称した追加効果を出さない。
- 復旧を選ぶことは封じ込めを飛ばす意味ではない。全対応に基本の封じ込め・安全確認を含み、重点配分を選ぶモデルと明示。
- 数値はゲーム用の仮定。現実の対策効果や復旧時間を保証する値ではない。

復旧に先立つ復元元の健全性確認と、戻したシステムの確認は、[NIST SP 800-61r3 のRC.RP-03・05](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-61r3.pdf#page=42)を確認した。現実では封じ込め・根絶・復旧を単独の3択で完了できるわけではない。

設備別の比較は、対応時の状態から**その設備だけをLv.0にした場合との差**。教育で過去に増えた文化や、自動化で以前確保した工数まで巻き戻す比較ではない。連携があるため各行は合計できない。これらの制約を画面にも明記した。

## 年間シミュレーション

再現：`Tools/Verify-CompanyOps.ps1`。従来3方針×300年に加え、`CompanyOpsPlaytest.cs`の5方針×500年、序盤2方針×500回を実行。
乱数シードは0〜499。変更前後で同じシードと行動規則を使用。途中の試験調整は最終結果へ混ぜない。

仮想プレイヤーは公開される予測の上限と対応費を読み、「出費×2＋停止時間」が小さい方針を選ぶ。
本番の非公開の深刻度・正常だったかという真相や `Preview()` は行動選択に使用しない。
別集計の「他案に劣る案」は事後診断であり、プレイヤーが未来を知っていたという扱いではない。

### 修正後の年間結果

| 行動規則 | 完走/500年 | 平均得点 | 平均累計被害(万円) | 平均累計停止(h) | 遮断/限定/復旧の選択数 |
|---|---:|---:|---:|---:|---|
| 放置・限定対応固定 | 152 | 0 | 251.76 | 170.45 | 0 / 5841 / 0 |
| 復旧設備Lv.1を優先 | 500 | 1083 | 76.99 | 64.70 | 1500 / 4499 / 1 |
| 台帳・教育・監視を優先 | 500 | 1287 | 58.61 | 36.78 | 0 / 6000 / 0 |
| 工数・組織からLv.2を優先 | 491 | 1658 | 23.45 | 39.32 | 1171 / 4606 / 178 |
| 社内依頼の現場ルートを優先 | 500 | 1525 | 68.69 | 30.45 | 0 / 5500 / 500 |

**まだ限定対応が強い。** 復旧選択が0回から増えたからといって、3択の完成度が十分になったとは扱わない。
「復旧設備Lv.1優先」規則は、毎月の提案にも工数を割くため、最初の月に訓練まで揃わない。方針名と実際の行動の差にも注意。
後半の6か月は、活動する4方針でも各500年あたり900〜1755月が投資なし。後半の事業目標・仕組みの更新・社員の変化は依然不足している。
高い完走率は入門向けの因果が成立する確認であって、高難度の戦略性の証明ではない。

### 最初の3か月の比較

初月の4工数を使い、復元型はバックアップ・訓練・手順、把握型は台帳・監視・教育へ投資。その後は同じ優先順で認証・教育・手順・更新を補う。
どちらも公開予測から対応を選ぶ。各500回の平均。

| 始め方 | 4月 被害/停止 | 5月 被害/停止 | 6月 被害/停止 | 6月末の予算 |
|---|---|---|---|---:|
| 復元連携から | 0.74万円 / 2.97h | 2.98万円 / 10.06h | 5.31万円 / 2.44h | 22.65万円 |
| 台帳・監視・教育から | 7.86万円 / 6.17h | 1.58万円 / 1.65h | 1.73万円 / 1.75h | 22.96万円 |

復元型は4月に強いが、認証事件の5月は広く停止する方針を選び、業務影響が大きい。把握型は4月のデータ被害が多いが、5〜6月を限定対応で進めやすい。
これは二つの実行可能な導入順に違いがある証拠。全選択肢の最適性や、プレイヤーが本当に迷うことの証明ではない。

## トレンド・近いゲームの追加確認

前回の[12作品前後の研究](Game-Experience-Research-2026-09.md)に加えて、今回は最近の公式更新から、改善判断の根拠を確認した。

- [Against the Storm 1.11公式更新](https://steamcommunity.com/app/1336490/announcements/?l=english)：住民表示、状況通知、効果の具体値、操作不能の理由、チュートリアル文言などの改善。そこから本作では「派手な飾りの追加」だけでなく、成長目標からの行動導線と選択前の比較を重視した。これは本作向けの解釈であり、ヒット要因の証明ではない。
- [Two Point Museum Update 10.0](https://community.twopointcounty.com/two-point-studios/two-point-museum/blogs/120)（6月18日）：調査を最大まで進めた場所で展示物を指定できる。追加費用・時間が必要で品質は保証しない。情報や育成への投資によって選択を狙いやすくしつつ、代償を残す例として確認。今回、設備抽選や展示物の模倣はしていない。
- [CygamesのUI・アニメーション試作講演](https://speakerdeck.com/cygames/2026-shadowverse-worlds-beyond-ui-to-animeshon-de-jitsugen-suru-saikou-no-yuza-taiken-o-kanaeru)（講演8月30日・公開9月25日）：見栄えと手触りを試作で確かめる考え方を再確認。本作でも購入・結果を実画面で操作する検証を継続。

最新版の網羅調査、全作品の購入プレイ、売上の独自調査ではない。ランキングとUIの良さは別であり、「今流行っているから同じ見た目にする」とは判断しない。

1. 実際の初見プレイヤーに3か月だけ遊んでもらい、次に買いたいものと理由を言えるか、復旧の使い分けが伝わるか確認する。
2. 後半の設備購入以外の目標を一つ試す。事業拡大、引継ぎ、社員の自発的な相談など。新しいゲージを大量に増やさない。
3. 限定対応を弱体化するだけでなく、状況に応じた選択理由を増やす。完全情報や理不尽な即死で難度を作らない。
4. ひなたの最終原画・背景の統一・BGMの選曲は別の未完了項目。今回のロジック改善で解決したとは扱わない。
