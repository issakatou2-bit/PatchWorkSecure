# UI・UX再調査：文字を読ませる前に状況と選択を伝える

調査日：2026-09-28。対象は新試作 `CompanyYear`。今回は調査のみ。ゲーム本体・シーン・ビルドは変更していない。

## 結論

現状の問題は、文字数に加えて「何を先に見るか」「何と何を比較するか」が画面から伝わりにくいこと。育成目標、相談、助言、予測、加算内訳が競合し、判断する前に文章を整理する必要がある。

方向性は、**オフィスと社員を主役にし、その時に必要な判断材料を近くにまとめること**。数値や学習内容を消すのではなく、常時表示・選択時の比較・任意の詳しい説明に分ける。フォント交換や角丸の追加だけでは解決しない。

## 調査の範囲と限界

- 2025〜2026年の6作品と、継続運営・複雑な数値表示の参考として2作品を比較した。
- 公式紹介画面、開発ブログ、公式更新情報を使用。紹介画像が各作品の最新ビルドと完全に一致するとは限らない。
- 下記の画面をブラウザーで目視確認した。Two Point Museumは公式更新本文を確認し、比較GIFでは更新前のフレームを確認した。更新後の改善内容は本文に基づく。
- 全作品を購入して通しで操作した調査ではない。静止画だけから、操作感・演出のタイミング・音・楽しさの効果は断定しない。
- 市場全体の流行や売上との因果を証明する調査でもない。以下の採用案は、このゲームに対する設計仮説。

### 1. 主役が定まらない

上の6つの資源表示、左の3つの能力表示と成長目標、右の相談、下のひなたと社内依頼が同時に目に入る。対応を選ぶ場面でも育成情報が同じ位置に残り、今の危険と今後の目標を視線で切り分けにくい。

対処案：月・予算・残り工数は常設。対応中は当該案件と関連する状態を強め、成長目標は縮める。表示を完全に消して探させるのではなく、概要と展開先を残す。

### 2. 選択肢が文章の塊になっている

対応画面は、事件名・症状・証拠説明の下に3つの加算ボタン、その下に3つの対応カード。それぞれ名前・予測・トレードオフ・加算の4行を持つ。選択肢だけで12行あり、注意書きも別にある。

対処案：3案の「対応費・停止・被害見積もり」を同じ位置・同じ単位で並べる。設備と社員の加算詳細は各案から確認する。現在の加算ボタン3個とカード内の内訳を常時二重に並べない。

費用や停止の重大な不利益は詳細に隠さない。予測の前提・未確定・範囲も残す。色で正解を教える設計にはしない。

### 3. オフィスとルールのつながりが弱い

オフィスには既に操作の入口があり、単なる飾りではない。ただし、どこで問題が起き、誰がどの作業を支えているかは、主に別パネルの文と数値で読むことになる。

対処案：対象部屋の印、設備の動作／停止、社員の担当表示を主な状況表示にする。通常時にアニメーションを増やすだけではなく、判断と結果に対応した変化を置く。

### 4. 比較すべき数値より補助文が増えている

月初のニュース・上司の相談・社員の声・ひなたの助言・依頼条件が並ぶ。必要な背景はあるが、同じテーマを複数の文章で読む負担がある。小さい補助文字も多い。現行UIは1600×900基準で縮小されるため、1280×720では読みにくさが増す。実際の文字高さとコントラストの計測は今回未実施。

対処案：月初は相談を主役にし、ニュースの見出しと根拠をそこへ結び付ける。ひなたはその場の一言。導入や行動の増減は、関連するゲージや数値のそばへ出す。

## 次に作るなら、この3画面を優先する

以下は未実装の案。新しいゲーム機能を増やすより、既存ルールの伝わり方を先に変える。

| 場面 | 最初に見せるもの | 視覚で伝えるもの | 必要時に開くもの |

| 月初・計画 | 今月の相談、使える予算と工数、主要な作業・導入候補 | 工数の枠、設備の絵と段階、社員の担当、選択による能力の増減 | ニュース本文、制度の説明、全能力、導入条件・内訳の詳細 |

| 月報・年間評価 | 結果、主要な増減、活躍した社員、次の操作 | ゲージの変化、設備→社員→成果のつながり、月ごとの履歴 | 全記録、細かい採点、用語解説 |

表示の約束：

- **項目名と単位は残す。** 予算・信頼・疲労を色や絵だけにしない。
- 色の役割を固定し、増減の符号・形・短いラベルも併用する。選択状態と危険状態を同じ表現にしない。
- 顔アイコンは「誰が助けたか」、設備アイコンは「何が効いたか」を示す。説明文の横に飾りを足すだけで終わらせない。
- 詳細は対象の近くに出し、ホバーだけに依存しない。キーボードの焦点やクリックで固定して読めるようにする。
- 予測と確定結果を見た目で区別する。不確実な見積もりを確定値らしく見せない。
- 一律に選択→確認の2操作へ増やさない。購入など不可逆な操作の確認と、通常操作のテンポは分けて検証する。
- 音や動きは情報を補う。成果の意味が分かる前に派手な演出だけを増やさない。短縮・抑制も用意する。
- 入門解説とSC寄りの詳しい説明は残すが、毎回すべてを読むことを進行条件にしない。

アクセシビリティの基準として、Microsoftの[文字表示](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101)、[コントラスト](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102)、[複数の手掛かりによる伝達](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103)を参照する。文字高さはフォント設定値ではなく実描画で確認。色だけに頼らず、音を切っても結果が伝わる構造にする。

## 検証のしかた

次は全画面の作り直しではなく、**対応選択の1画面**で比較するのがよい。現在の画面と、情報を整理した試作を同じ案件・同じルールで比べる。

検証目標（今回測定した結果ではない）：

1. 初見で5秒程度見た後、「何が起きていて、何を選ぶ場面か」を説明できる。
2. 長文を読まずに3案の費用・停止・被害の違いを見つけられる。判断の根拠は必要に応じて確認できる。
3. 行動後に「何が増減し、設備や社員がどう役立ったか」を取り違えない。
4. 対応画面の常時説明文は現状の半分程度を目標にする。ただし重要な不利益・前提は削らない。実装前に可視文字数と読了時間の基準値を取る。
5. 720p／1080p、文字拡大、キーボード操作で、切れ・重なり・焦点の見失いがない。

人間のゲーマー・IT初学者・FE相当の知識がある人で、情報を探す時間、読み間違い、選択理由、疲れやすさを確認する。自動完走やAIの仮想プレイでは、初見の読みやすさ・楽しさを確認したことにはならない。

## 9/28：対応画面への初回適用

研究だけで終わらせず、CompanyYearの対応画面に限定して実装した。月初・月報は今回の全面改修対象ではない。

- 左にオフィスの確認対象と社員の支援、ひなたの一言。右に事件の症状と3案の比較。成長目標を対応中に常設しない。
- 3案で費用・被害・停止の順序と表示位置を統一。被害と停止は同じ単位ごとの共通尺度で幅を表示。抑制力は短い数値と詳細の入口へ。
- 未確認／調査済みを常設し、証拠・知識・設備／担当者／社員の内訳はクリックで開く。未調査の真相を見積もりに混入しない。
- 未確認の対象は「確認対象」と表示し、侵害が確定したアニメーションや犯人の印を描かない。
- 対応開始のトーストが比較カードを覆わないよう変更。720pで数値欄が切れる問題を実画面で発見し、表示枠を修正。
- 数式・費用・年度抽選・セーブ形式・既存の選び分けルールは変更していない。見積もりの構造化は既存Forecastと同じ値。

参考作品から採るのは、キャラや配色の複製ではなく「行動前の増減が比較でき、支援者と成果が結び付く」という構造。[ウマ娘の育成と仲間・スキル](https://umamusume.jp/contents/game/system/)、[シャインポストの投資・育成・成果](https://www.konami.com/games/shinepost/gamemode/)を再確認した。
初見での理解速度や楽しさが改善したかは、人間の比較試遊で未検証。情報量を削っただけで成功としない。
