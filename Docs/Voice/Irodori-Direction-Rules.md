# Irodori-TTSで声を作るときの決まり（Claude、2026-10-02）

加藤さんの指摘（10/2）：「単語ごとのイントネーションがおかしい」「会話のトーン・テンションになっていない」「イントネーションは本当に気を使って。これで急に萎える人も多い」。その4→その6の聞き比べで分かったことを、決まりにする。

## 1. 声に渡す文

- **ふつうの漢字かな交じりで書く。** ひらがなだらけにすると、単語の切れ目と高低（アクセント）の手がかりが消えて、単語ごとに不自然な抑揚になる（その4の失敗）。
- かなにするのは、**読み違えると分かった語だけ**（例：「三行」→「さんぎょう」、「保守ID」→「保守アイディー」、「今日」→「きょう」）。
- 読点を増やしすぎない。息つぎの位置だけに打つ（読点ごとに区切れて、たどたどしくなる）。
- 長い文章（朗読）は、1回に渡す長さを50〜60字ほどまでにし、文の切れ目で分けてつなぐ。

## 2. 話し方の指示（キャプション）

- 声の説明だけでなく、**場面・相手・気持ち**を1行ごとに書く。例：「机で居眠りしている同僚の肩を軽く叩いて、小声で、少しからかうように起こす」。
- 共通の一文：「同僚どうしの、オフィスでのくだけた会話。読み上げではなく、目の前の相手に話しかけている。」
- 絵文字で話し方を指定できる（一覧はモデルに同梱の`EMOJI_ANNOTATIONS.md`）。よく使うもの：😏からかう、🤭含み笑い、🫶優しく、😪眠そう、😆喜び、😊楽しげ、😎得意げ、😟心配、😲驚き、😮息をのむ、⏩早口、🐢ゆっくり、📖独白、⏸️間。
  - 一覧に無い絵文字（😅など）は使わない。
  - 短い語の直後に置くと、その語が崩れることがある（「たぶん🫣」→「飛ぶ」）。文の終わりか、句の前に置く。
- **説明に打ち消しを書かない。** 「電話のような音は無い」と書いたら、16通り中15通りが通話のような音になった（言葉そのものに引っぱられる）。望む音だけを書く。
- **見本にこもった音を混ぜない。** 見本の1本がこもっていると、作る声もときどきこもる（その7の原因）。見本は0.5秒ごとに高い音の量を調べ、こもりが無いものだけを使う（`Tools/Irodori-Hinata9.py`の`muffled`）。
- 見本の声への寄せ方（`--cfg-scale-speaker`）は**3**、指示の効き（`--cfg-scale-caption`）は**5**。寄せ方が強いと、どの台詞も見本と同じ調子になる。

## 2b. 朗読（長い文章）のトーン（10/3、加藤さん）

- **朗読は、話すときより声を低く落とし、落ち着いたピッチで読む。** 会話と同じ高さで読むと、文章を読むには軽く聞こえる（ElevenLabsの完成形もこう読んでいた）。説明に「話すときより声を低く落とし、落ち着いたピッチで、ゆったりと朗読する」を入れる。
- 速さは人物に合わせる。りりぃは朗読だとゆっくりすぎるので0.85倍（会話の台詞の0.8倍と同じくらい）。
- ひなたの朗読は「社会人の若い女性が、絵本を読み聞かせるように。幼くしすぎず、大人の落ち着きも少し残す」。「子どもに読み聞かせる」と書くと声まで幼くなる。
- 区切りごとに声がぶれるのを減らすには、`--truncation-factor 0.9`（揺れを小さくする。下げすぎると表情も減る）。
- 種（seed）が違うだけで単語の高低が変わる（かのんの「数字」は種20261002だと不自然、20261003・20261004は自然）。1本だけで決めず、2〜3通りを人が聞いて選ぶ。
- 読み違えた語の一覧（かなで渡す）：山路→やまみち（「さんろ」と読む）、三行→さんぎょう、保守ID→保守アイディー、今日→きょう、母さん狐→かあさんぎつね、智に→ちに、角が立つ→かどが立つ、水の面→水のおもて。見つけたらここに足す。

## 2c. 声の候補の選び方（ひなた、10/3）

- 見本なし（文字の説明だけ）で作った声は、行ごとに声が少しぶれる。気に入った候補は、その候補のこもりの無い2〜3本を見本にして固定してから、全部の行を作る。
- 加藤さんの好み（その9）：元気で可愛いが、あざとすぎない・落ち着きすぎない。H01・H02・H06・H08・H09・H16が候補。

## 2d. 見本は「調子のそろった1本」（10/3）

- 見本に調子の違う声（元気・しょんぼり・得意げ）をつなぐと、区切りごとに違う調子を拾い、文ごとに読み方が変わる（ElevenLabsの16本をつないだひなたの見本で起きた）。見本は、軸にしたい1本（ひなたは「おはようございます」）にする。かのん・りりぃが安定しているのも、見本が1本だから。
- 速さの目安（朗読）：かのん0.9倍、りりぃ0.78倍。かのんの朗読は「いつもの話し声よりはっきり低い、深みのある声」。

## 2e. GPUの順番（10/3）

- Codexのテスト（Unityの`-runTests`）が動いている間は、声の生成を待つ（`sh Tools/Wait-GpuFree.sh && <生成>`）。取り合うとテストが時間切れで失敗することがあるので、テストを優先する。

## 3. 確かめ方

- 1行につき3通り作り、人の耳で選ぶ。機械の確かめは「ふるい分け」にとどめる。
  - 書き起こし（faster-whisper）：読み違い・言葉の崩れを見つける。ただし同じ音の別の字（「三行」→「産業」）は書き起こしの都合で、声は正しい。
  - 4kHzより上の音の割合：通話のような、こもった音を見つける。
- **書き起こしでは高低（アクセント）の誤りは分からない。** 最後は必ず通しで聞く。会話は前後の行とつないで聞く（1行だけでは自然に聞こえても、つなぐと調子が合わないことがある）。

## 4. モデル

- かのん：大型（量子化版）でも新しい小型でも良い（その6のc・d）。りりぃ：小型。ひなた：大型で探し中（その9→その11で6候補に絞る）。小型のSA1はぶれが多く不採用。
- 大型の完全版（13GB）はこのPCのグラフィックボード（8GB）に収まらない見込み。量子化版との音質の差は小さいのが普通で、違和感の主な原因は1・2章のほう。
